# 通知后端（V1 外提案）

## 背景

Issue/PR/部署状态变更目前依赖用户主动刷新控制台或审计查询，缺少面向租户的**可投递通知**（邮件、Webhook、应用内收件箱）。

## 建议能力（待审）

- 事件源：Issue 指派/关闭、PR 审查与 CI、部署审批与结果、组织成员邀请。
- 投递通道：Webhook（首版）、可选 SMTP（运营方配置）；不含移动端推送。
- 订阅模型：按 org/repo 与用户偏好；默认仅关键事件。

## 收益

- 降低「忘记审批/遗漏失败部署」的运营风险；贴合 S1–S4 中审查者与发布者角色。

## 代价

- 新表（subscriptions、delivery_attempts）、出站队列 worker、重试与退避、密钥管理与审计。
- CI 需隔离出站 mock；与现有 audit 事件去重或派生，避免双写不一致。

## 建议决策

- **不在本仓库当前批次实现**；若批准，单独立项于 `cursor/notifications-v1-*`，在 audit 事件稳定后再做消费端。
